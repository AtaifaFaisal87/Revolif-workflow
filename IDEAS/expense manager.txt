================ USER AND EXPENSE MANAGER RELATIONSHIP ================


The User has a composition relationship with ExpenseManager because financial data belongs to a specific user.

Each User contains their own ExpenseManager object, which manages all income and expense transactions of that user.

When a User exists, their ExpenseManager exists with them.

Each transaction is linked to that specific user's ID.

User financial data remains private and isolated from other users.



================ EXPENSE MANAGER AND STATISTICS RELATIONSHIP ================


Statistics has an association relationship with ExpenseManager.

Statistics does not store financial data.

It only reads ExpenseManager data and generates reports.


Example:


ExpenseManager

        |

        ↓

Statistics

================ DESIGN REASONING ================


Transaction class represents one financial activity.

ExpenseManager manages all transactions of one user.

Statistics analyzes financial data but does not modify it.

Using one Transaction class avoids unnecessary inheritance because Income and Expense share the same attributes.

The design supports future features like:

- Budget Management
- Saving Goals
- AI Financial Advice
- Spending Predictions
- Monthly Financial Health Score
