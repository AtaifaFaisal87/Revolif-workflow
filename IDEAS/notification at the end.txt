================ USER AND NOTIFICATION RELATIONSHIP ================


The User has a composition relationship with NotificationManager because notifications belong to a specific user.


Each User contains their own NotificationManager object.


Example:


User A


|

NotificationManager


|

Notifications:

- Task deadline reminder

- Goal achievement

- Badge unlocked



User B has separate notifications.

================ DESIGN REASONING ================


NotificationManager centralizes all alerts from different modules.

Individual managers only generate events and do not handle notifications.

Notification class represents one alert.

EmailService handles sending emails separately.

This design keeps modules independent and allows future additions like:

- Push notifications
- Mobile app alerts
- Smart AI reminders
- Custom notification settings
- Notification history
